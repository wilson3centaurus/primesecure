# Prompt school sync (agent 0.6.8, version code 14)

The pilot already reported strict=true and eight hidden apps at 19:39 on 15 October 2026. Its later DNS/socket errors were followed by connection recovery. Firmware apps, including PrimeOS Settings and the vendor store, remain protected by the earlier boot/login safety fix. This release preserves those protections. Installed-app inventory includes hidden apps; the dashboard now shows reported Hidden on device / Suspended badges.

Library and settings tables intentionally restrict direct device reads, which also limits their Realtime events. Instead of widening those permissions, triggers now increment a durable sync_revision on affected enrolled device rows for school/global settings, policy, apps/notes/wallpapers and school-access changes, including removal. Device RLS already permits reading only its own row. Pending revisions survive disconnection and repeated restarts. No new read access to school staff or other student records is granted.

The foreground agent responds to that device-row change with a coalesced direct check-in. One active policy application is allowed to finish; bursts retain one follow-up request. A lightweight revision check every 30 seconds while connected catches missed signals, and network reconnection requests a check-in. WorkManager remains the durable background fallback; background service/network availability and a slow server can delay delivery. There is no unconditional two-minute delivery guarantee.

The student receives a school-update notification and an in-app status banner for pending/applying/waiting/applied changes. These are nonblocking. The server records an acknowledgement only after the library list is fetched and policy application reports no problems. An unavailable catalog no longer silently replaces the managed policy with a partial baseline policy. Concurrent older catalog responses cannot overwrite a newer revision.

Settings acknowledgement is distinct from downloading all books, wallpaper images or apps. Those continue in Background tasks with their existing progress displays. New revisions can request a download-worker follow-up; regular polling coalesces with existing downloads. The dashboard's School sync card shows requested/applied revisions and times, and provides Sync now. Offline devices remain pending and catch up after reconnection.

The database migration must precede installation of 0.6.8, because the agent uses the new device_sync_state and device_ack_sync RPCs. Older agents continue using their existing check-ins but cannot acknowledge the new revisions. The migration was tested for school isolation, denied forged writes, monotonic acknowledgement, changes during an in-flight sync, library deletion/access removal, device-specific policies and a 300-device school fan-out.

Update with the same-signed, non-test-only APK through Agent updates. Physical validation still requires installing it on the pilot, changing one harmless setting/library entry, observing the student notification and School sync acknowledgement, then checking offline/reconnection behavior. No mass rollout or additional firmware hiding is authorized by these checks.
